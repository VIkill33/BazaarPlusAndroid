# 设计：点击收藏角标查看构筑缺卡

分支 `feat/android-custom-build-ui`。规模：小改动（一个弹窗类、一个纯规则函数、角标类的点击接入）。

## 意图

对局中，可选卡牌左上角的角标表示它属于某套「提醒中」的收藏构筑。玩家点角标，是想马上知道
**这套构筑还缺哪些卡**，从而判断眼前这张卡值不值得拿。看一眼就回到对局。

## 目标

- 点角标弹出小面板，用真实卡面展示该卡所属的一套提醒中构筑，保留玩家摆放的格位。
- 每张卡下方标注状态：【场上】【背包中】【本次可选】【未拥有】。
- 一张卡同属多套构筑时可左右翻页，显示「第 N / M 套」。
- 底部一行汇总「已有 N / M 件 · 还缺 K 件」。

## 非目标

- 不在面板里编辑、删除构筑或开关提醒。
- 不跳转到「我的构筑」页。
- 不改构筑推荐页的「仓库」用词；「背包中」只用于新面板。
- 未开提醒的收藏构筑没有角标，也不进入翻页。

## 反目标

- 点角标或点面板时触发游戏的选牌、购买。
- 修改任何游戏拥有的卡牌对象。

## 做法

考虑过三种：

| | 做法 | 取舍 |
|---|---|---|
| **A（用户选定）** | 独立小弹窗，`AndroidBuildBoard` 画卡面，卡下加状态标签 | 卡面一眼可认，绘制与持有读取都有现成代码；需新增一个弹窗类 |
| B | 跳进全屏「我的构筑」页并定位 | 打断对局；该页没有翻页与持有状态，改动更大 |
| C | 纯文字清单 | 代码最少，但中文长卡名靠读，辨认慢 |

## 设计

### 状态规则（纯函数，可离线测试）

新增 `CustomBuildOwnership.Classify(items, board, stash, offered)`，放在
`android-mod/CustomBuilds/`，不依赖 Unity：

- 输入：构筑物品（按格位顺序）、场上与背包各模板的**张数**、本次可选的模板集合。
- 每件物品依次取：场上还有余量 → 场上；背包还有余量 → 背包中；在本次可选里 → 本次可选；否则未拥有。
- 按张数消耗：构筑里同一张卡出现两次而玩家只有一张时，只有第一件算已有。
- 「已有」= 场上 + 背包中；「还缺」= 其余。

### 持有读取

场上、背包、本次可选的读取逻辑现在内联在 `AndroidBuildPanelController` 的刷新方法里
（`player.Hand.Container`、`player.Stash.Container`、`Data.CurrentState.SelectionSet`）。
抽成一个公用静态方法，返回张数字典；构筑推荐页改为调用它，行为不变。

### 角标点击（`AndroidFavoriteMarks`）

- `_stars` 由「模板 → 颜色」改为「模板 → 提醒中构筑列表」，颜色从构筑推出；角标仍最多画三枚。
- 角标画布加 `GraphicRaycaster`。每张带角标的卡一个透明点击热区，盖住整簇角标，
  边长不小于约 72 像素。菱形本身仍不接收射线。
- 点击 → 打开弹窗，定位到该卡的第一套构筑。
- 弹窗打开时角标与热区隐藏（并入现有的隐藏条件）。

### 弹窗（新类 `AndroidFavoriteBuildPopup`）

- 自有 ScreenSpaceOverlay 画布，层级与构筑推荐页相同（30001），带 `GraphicRaycaster`。
- 全屏半透明遮罩吃掉所有触摸；点遮罩或「关闭」收起。
- 居中面板：标题行（构筑色菱形 + 构筑名 + 「N / M」+ 关闭）、中部 `AndroidBuildBoard`
  （`keepSlots: true`）、两侧 ◀ ▶（仅一套时隐藏）、每张卡下方的状态标签、底部汇总行。
- 状态标签颜色沿用构筑推荐页：场上绿 `8FE39A`、背包中蓝 `82B8FF`；本次可选用金色，未拥有用弱化色。
- 构筑名、配色、按钮皮肤沿用 `AndroidCustomBuildPanel` 与 `AndroidPanelButtonSkin` 的现有做法。
- 状态在打开和翻页时计算一次，不逐帧刷新。
- 生命周期：翻页、关闭时调用 board 的 `Hide()` 清理原生卡面；构筑、图鉴、历史面板打开，
  长按预览激活，对局结束或 `SelectionSet` 变空时自动关闭。
- 日志：`android.favorite_popup.opened template=.. builds=..`、`.paged index=..`、`.closed`。

## 约束与风险

- 角标提交 `a17201f` 及其前两个提交**未编译、未真机验证**；先按
  `bazaarplusplus-android/docs/handoff-custom-build-verification.md` 第 0–1 步让分支编译并通过离线测试。
- 角标画布层级为 5。游戏自身 UI 若盖在其上，热区可能点不到，或挡不住游戏的选牌输入。
  这只能在真机确认；点不到时把热区移到单独的高层级画布。
- 持有读取目前只在构筑推荐页用过，需在商店、奖励、事件三种选牌界面真机确认。

## 测试

- 离线：`CustomBuilds.Tests` 增加 `Classify` 的断言（四种状态、重复卡按张数、优先级）。
- 真机：按根 `AGENTS.md` 第 4 节；标准与高级输入模式各一遍；确认点角标不选牌、翻页卡面无残留、
  关闭后角标恢复。不购买、不选择奖励，除非用户当次授权。
