# BazaarPlusAndroid

对外名称统一为 `BazaarPlusAndroid`，折叠入口简称 `BPA`。为保持覆盖升级、原有数据和 JNI 兼容，
应用 ID、插件 GUID／程序集／命名空间、内部配置键及既有存储目录保留原值；上游署名与历史验证证据保留原名。

游戏顶部不再显示历史记录状态提示条，等待、记录、保存和异常状态均不显示。

战斗播放期间默认在底部居中显示计时器，可单独拖动，松手后吸附到最近的屏幕边缘（上下保留安全区域），
位置自动保存，分辨率或安全区域变化后按已保存的边缘位置重新布局。格式为「分:秒.百分秒」，按游戏实际播放的战斗帧计算时长；
每次实战或原生回放从零开始，战斗结束保留本场时长，离开战斗场景隐藏。
游戏原生设置「BazaarPlusAndroid：战斗计时器」可选择显示／隐藏，默认显示，保存到插件配置 `combat-timer.json`；
隐藏不影响战斗播放或计时进度。此功能不新增历史战斗回放入口。实际验证范围见[真机记录](docs/device-validation.md)。

当前提供实验性 Android IL2CPP 游戏内图鉴、运行时检查工具和加载探针，尚未提供完整安卓模组。

`launcher/` 已接入单 APK 专用测试启动器：中英文首页、授权引导、固定游戏兼容检查、
内置框架、插件与匹配的 Unity 依赖、离线提取校验、失败重试、修复、会话加载确认。
初始化与修复无需访问 GitHub；游戏登录及游戏自身资源下载仍需联网。
启动器 test.12 将 BepInEx 的 Unity 基础库来源固定为清单中已校验 ZIP 的本地文件名，
避免内置 `6000.3.11.zip` 与来源 URL 末尾的 `Managed.zip` 不一致，误读旧缓存或尝试联网。
离线 ZIP 消费回归与签名构建通过；用户已确认 test.12 修复包验证通过。
按用户要求未覆盖安装当前手机；反馈未逐项列出设备和验收步骤，详细覆盖范围见真机记录。

启动器首页、离线帮助、设置、游戏选择、准备进度及已知错误提示随系统语言显示中英文，其他语言回退英文。
游戏内插件独立跟随游戏语言，切换语言时更新预览标签并清理构筑及附加预览的旧语言缓存；
本次资源／Java 编译与离线回归通过，完整插件编译及真机英文验收仍待补齐，详见真机记录。
配置保护 DEX 的读取已改用兼容旧版 Android 的缓冲循环，避免 Android 9 准备阶段因
`InputStream.readAllBytes()` 缺失退出；离线与 Android 14 独立文件测试通过，签名覆盖安装后新会话加载与游戏主菜单验证通过，Android 9 完整启动待验证。
启动器 test.11 修复旧版 Android 的显示对象适配：API 26–29 通过宿主 Activity 的
`WindowManager` 提供 Display，避免配置变化时系统解引用空值。离线分支回归、Android 14 新会话加载和主菜单检查通过，
原小米 9／Android 9 的完整启动仍待复测；实际设备范围见真机记录。
游戏退到后台后，再点桌面启动器图标会返回原游戏界面；重复入口不重新初始化游戏。
使用独立应用身份和运行目录，不迁移原 FusionCore 环境；首次登录由用户在游戏内完成。
当前构建与设备验收范围见 [真机记录](docs/device-validation.md)，
构建方式见 [启动器构建说明](launcher/BUILDING.md)。公开发行许可审计、第二台设备与
故障恢复验收尚未完成；未提供远程 DLL 更新或自动 APK 更新。

启动器首页参考[暮紫琥珀原型](docs/design/launcher-concept-c.md)，使用独立集市背景、
英文品牌、启动前状态和琥珀主按钮；横屏可滚动，系统字体大小变化会重新排版。
首页按钮采用[第二版网格布局](docs/design/launcher-home-grid.md)：全宽启动按钮，下方两行三列依次为
「对局历史／设置／帮助」和「重新检查／打赏作者／Github」，底部为「更多：修复与许可」。
「Github」点击通过系统打开本 Android 项目的
[GitHub 仓库](https://github.com/VIkill33/BazaarPlusAndroid)；无可用处理应用时显示「无法打开链接」。
首页「帮助」提供离线使用说明，保留深棕底色、暖金分隔线与琥珀按钮。
三步引导涵盖安装授权、首次启动和插件入口；游戏内操作集中说明图鉴、构筑、
长按／双指按住预览、入口拖动与自动收起，并提供客户端切换和故障反馈指引。
首页「设置」可改选本机带桌面入口且已提取 arm64 IL2CPP 原生库的游戏；未选择时仍启动正版。
选中后首页「启动游戏」启动该游戏，帮助页说明筛选条件、Unity 版本核对与各自的运行目录。
「更多：修复与许可」保留安装、授权、修复、诊断日志导出及开源许可。导出由用户选择保存位置，只含启动器自己的准备记录，不含游戏日志、账号或登录数据，也不会自动上传。启动失败时会分条记录脱敏后的 Java 异常原因链和调用栈，
避免 Unity 的外层错误包装遮住真正原因；该诊断改进尚待受影响设备验证。
「可以启动」仅表示启动前检查，不代表游戏登录或插件功能验收通过。
插件入口组支持拖动整组位置，松手后吸附到最近的屏幕边缘（上下保留安全区域），并保存位置。
游戏原生设置新增「BazaarPlusAndroid：按钮自动收起」，默认关闭；开启后闲置 5 秒收为边缘瘦长悬浮条，B、P、A 自上而下竖排，
点击展开入口按钮，也可点「收起」立即折叠。悬浮条同样可以拖动吸边；
拖动不会执行按钮操作，图鉴或构筑面板打开时隐藏入口组。
重复设备验收使用 `verify_floating_dock.py --help`（需要 Pillow）；先启用自动收起并关闭设置，
使用默认左边距 0，脚本验证四边吸附、原有三个按钮拖动及展开／收起。
中档入口为 115×140（参考 1080 屏高，按屏高缩放）的图标按钮，图标下方显示短名称：图鉴、构筑、长按模式、
按住预览、历史；隐藏的入口不占位，按钮组随之收紧。长按模式按钮的图标与文字随「附魔／升级／无」切换。
图标按钮使用游戏设置按钮的原生圆形金色边框，图标居中，文字位于圆框下方并加粗、带黑色阴影；图标周围不再显示深绿色方块。游戏原生设置「BazaarPlusAndroid：按钮图标大小」提供大（1.5 倍）、中（1.2 倍）、小（1 倍），默认中档，切换时圆框、图标、文字及按钮间距同步缩放，并保存在 `dock.json`。边框资源暂未就绪时保持透明底，待游戏资源出现后补上边框。
游戏原生设置「BazaarPlusAndroid：按钮样式」可切回旧版 270×90 纯文字按钮，即时生效并保存在 `dock.json`；纯文字按钮及收起手柄的文字同样加粗并带黑色阴影。
五个入口各有独立的显示／隐藏设置（游戏原生设置「BazaarPlusAndroid：…按钮」与启动器「设置 → 游戏内按钮」），默认全部显示，
保存在与面板位置共用的 `bpp-launcher-settings.json` 的 `hiddenDockButtons` 中；两端写入均合并已有字段。图标来源与许可见 `assets/dock-icons/SOURCE.md`，启动器许可页同步署名。

新增第四个「按住预览」入口，仅高级输入模式可用。按住时显示贴近屏幕左右边缘的淡金细边框（上下保留安全区域）及
「预览中 · 松开退出」顶部提示，背景以 55% 黑色遮罩压暗，当前卡牌加浅金描边；卡牌、原生详情与附加预览保持原色。
预览期间入口按钮组暂时隐藏，避免挡住详情，松开后恢复；持有按钮及全屏输入拦截保持有效。
另一根手指点击物品、事件或野怪，仅打开原生详情与现有附加预览，不转发选择、购买或拖动事件。
已打开的原生详情和附加预览面板不再挡住下方目标，按住期间可直接点被遮住的物品或事件切换；菜单等其他界面仍会阻挡。
松开、失焦、进入战斗、切换场景或退出高级模式时结束；松开时仍在屏幕上的其他触摸会被消费到结束。
松开「按住预览」后，已打开的野怪信息面板保留，可继续点击物品／技能查看说明，点击空白或 × 关闭；
切换预览目标、进入战斗或切换场景仍清理野怪面板。物品与事件附加预览继续随松开关闭。
标准输入模式隐藏此入口，仅高级输入模式显示；切换模式时按钮组同步调整排列和高度。此按钮用于按住，拖动整组位置仍使用原有三个按钮。
双指回归使用 `verify_hold_preview.py --help`；`--next-target` 可检查一次按住中连续换目标，
`--holder-first` 检查先松开模式按钮，自动收起开启时可用 `--expand-dock` 在工具准备后再展开入口。
野怪保留路径使用 `--expect-monster-retained`，检查保留事件并人工复核 `released.png`。
脚本断言插件日志和原生崩溃缓冲区，视觉仍需人工复核截图。

游戏原生设置的语言选项下方新增「BazaarPlusAndroid：长按预览」和「BazaarPlusAndroid：预览面板位置」下拉框。
长按预览可直接选择「附魔／升级／无」，与左侧快捷按钮共用并保存同一偏好；
面板位置可选择「默认位置／靠屏幕左侧边缘」，保存后后续预览渲染使用新位置，无需重启游戏。
首页「设置」仍提供面板位置选项，与游戏内设置共用持久化文件；启动器优先读取该文件，
避免下次启动覆盖游戏内选择。默认保持原布局，靠左保留安全区域边距、面板宽度及滚动。
首页「设置 → 图鉴与构筑页面样式」可开启「使用新样式」。默认关闭，保留旧样式；开启后卡牌图鉴和构筑推荐共用暮紫琥珀配色、集市背景及暖金控件边框，卡牌仍使用游戏原生图像。选择写入 `bpp-launcher-settings.json`，下次启动游戏时生效；关闭后恢复旧样式。筛选、预览、候选选择、构筑匹配和刷新规则不变。
设置作用于物品附加预览的共用面板（包括任务奖励页），事件与怪物面板位置不变。

`android-mod/` 包含使用 Android 互操作程序集编译的独立游戏内图鉴。其数据适配和
UGUI 触屏界面由 Android 层负责，筛选、名称搜索及本地化引擎通过源码链接复用桌面项目。
这不是桌面 DLL 的重新打包；桌面回放、视频录制与上传尚未接入。
游戏内双方历史阵容直接使用原生卡牌预览及其保存品质的原生边框，不再叠加线条边框或灰色卡槽底色；卡槽按实际宽度换算高度、全部 10 列紧密排列，技能同样 10 列一行；历史卡牌详情交互沿用现有行为。
历史功能采用[独立 JNI 桥和 Java 系统 SQLite](docs/adr/0002-local-history-storage.md)。M1 的事务存储、
有界串行写入、身份窗口规则及故障保留已实现；隔离真机覆盖回滚、空间不足、事务中强杀与较新／损坏库保护。
历史列表按一整局游戏分组，点入后仅列出各次 PvP 交手，再点入查看双方当时阵容。
新采集记录包含对手名称与英雄；旧记录未保存名称时明确标注。野怪原始战斗和回放均不采集快照，
野怪战斗不写入历史窗口、结果或诊断载荷；整局身份、进度及正常结算仍独立观察。
旧库中的野怪记录保留原数据，但不进入列表、PvP 场次或直接详情查询。
启动器首页「对局历史」进入「历史对局 → 单场对局 → 单场对战」三级页面，以暮紫背景、琥珀强调和日期分组的紧凑列表浏览；
页面标题直接使用功能名称，保留英雄筛选、分页及返回位置。单场对局的摘要可点击查看完整对局信息；败场字号为原来的四分之一、使用灰色，与胜场间隔五个胜场字号的全角字符宽度。
启动器历史可只读浏览当前目标游戏的本机档案、整局、战斗和双方二维阵容；
启动器列表对齐游戏内的英雄头像、突出胜场、奖杯与交手结果，支持按英雄筛选，筛选项在名称旁显示头像。
单场对战页的英雄头像按英雄名称实际行高缩小，与名称水平并列，不占物品和技能的独立列；字号变化时同步调整标题行预算。
单场详情按可用屏幕自动排版，横屏并列双方阵容、竖屏按实际内容高度紧凑上下排列；每方物品固定单行、统一图片高度并按游戏原生卡图比例显示，宽度不足时整排等比缩小，全部物品和技能一屏显示。
物品与技能只显示图片，并按历史快照品质叠加游戏导出的原生品质边框（青铜、白银、黄金、钻石、传奇；物品按小／中／大型导出 `frame-<体型>-<品质>.bppart`，技能导出 `frame-Skill-<品质>.bppart`）。物品插画位于原生边框窗口内；技能裁成圆形后叠加与游戏内历史页相同的品质环。边框缓存未生成前只显示插画；不展示名称、品质文字或点击／长按详情；技能图标边长上限为原 88dp 的四分之一，密集时继续缩小。
点击顶部战斗信息可查看对局与采集版本。每页大小由 `HistoryReader.PAGE_SIZE` 定义，只为选中战斗读取完整快照；
完整采集的物品／技能区只保留分组名，不显示完整采集状态或张数；未记录结果、部分采集和采集失败仍显示，浏览不会初始化、迁移或修复数据库。
启动器英雄图、奖杯和卡牌插画来自游戏插件生成的本机缓存，启动器读取图片时不联网。首次升级后需启动游戏并等待历史图片回填；
缓存按当前游戏版本隔离，补齐当前账号范围内的 PvP 历史模板，以及购牌统计在「全部英雄、全部」下常买排行和购买明细第一页的模板。更后面的购牌图片不再导出。图片仅供参考，不更改保存的品质、附魔及实例属性；
缺图时保留分组标签，非完整采集仍保留状态与张数，进入游戏后只补齐仍会显示的图片。来源、保留优先级和清理周期见[图片缓存决策](docs/adr/0003-history-art-cache.md)。
历史与购牌统计的新图片缓存写入 `BepInEx/history-art/.cache/v3/<游戏版本摘要>/`，使用 `.bppart` 后缀保存 PNG 字节；根目录和图片目录创建 `.nomedia`，每次落盘前补齐图片目录标记，失败时不发布图片。启动器每天第一次回到首页时，删除对局历史和购牌默认第一页用不到的卡牌图、其他游戏版本目录，以及不再读取的旧版图片树；占用超过 `HistoryArtCache.SIZE_BUDGET_BYTES` 且继续增长时会提前再清。设置里的「清理缓存」立即执行同一规则，并显示释放和剩余大小。英雄、奖杯、状态和品质边框图片保留。清理不修改历史数据库，也不改系统相册里已有的记录。进入游戏后，仍需要但被删掉的图片会重新生成。
首页「购牌统计」以[选定的第二版原型](docs/design/launcher-purchase-gallery.md)展示本机成功购牌记录：首名横向突出，其余双列卡图，展示购买次数、花费金币及记录对局数，支持英雄筛选、排行／明细切换、分页与点击详情。窄屏及 130% 以上字体改为单列，旋转和字体变化保留逻辑卡牌位置。图片读取现有本机历史缓存，图标留白与卡片按钮主体共用深棕底色，小型物品周围不再单独显示近黑占位块；未缓存时保留名称和统计；奖励不计入，旧对局无法补录。验收覆盖范围见真机记录。
顶部单行提供「全部／近三日／近七日／小型／中型／大型」六个互斥胶囊，宽高各约为最初两行方案的一半（面积约四分之一），始终与当前英雄筛选取交集，同时作用于排行、明细及汇总；切换条件回到第一页，旋转与字体变化保留选中项。近三日／近七日按刷新时刻向前 72／168 小时计算；体型仅统计物品，以本机游戏 `GameData.db` 当前模板分类，不改变购买记录，未在目录中的模板不纳入体型结果。目录缺失或不可读时明确提示，可继续使用全部或时间筛选。

`inspect_game.py` 使用 Python 3.9+ 标准库和 Android SDK 的 ADB。它自动寻找常见 SDK
目录中的 ADB，选择已授权的设备，复制游戏的 base APK 与所有 split APK 到本机，
生成含 SHA-256、ABI、原生库、Managed 程序集和 IL2CPP metadata 路径的 JSON 报告。
运行时分类基于原生库；未知或同时存在两种运行时的结果需要进一步检查。

```sh
python3 bazaarplusplus-android/inspect_game.py
python3 bazaarplusplus-android/inspect_game.py --serial DEVICE --package GAME_PACKAGE
python3 bazaarplusplus-android/inspect_game.py --apk /path/base.apk --apk /path/split_config.arm64_v8a.apk
python3 -m unittest discover -s bazaarplusplus-android/tests -v
```

默认报告与 APK 写入本目录被 Git 忽略的 `artifacts/device/`。通过 `--output` 可选择其他
目录。多个设备或不能唯一识别的游戏包名必须显式指定，未授权的设备直接报错。
工具只读取设备信息和安装包，不安装、卸载、重签或重启游戏，不读取游戏账号数据。
离线检查必须提供完整 APK 集；缺少 ABI split 时可能无法识别运行时。

## 独立加载探针

`probe/` 是 BepInEx IL2CPP 的 `BasePlugin.Load` 插件，不引用桌面模组或游戏程序集。
入口执行时写入 `android.bootstrap.loaded` 日志，并尝试在 BepInEx 目录写入
`bpp-android-probe.json`，记录运行时、架构、线程和路径。这个标记只证明插件入口执行，
不证明 Unity 帧回调、图鉴或其他游戏功能已经可用。

框架来源和 SHA-256 由 `toolchain.json` 固定，构建工具先校验再提取引用程序集。
从该版本的 [FusionCore 源码](https://github.com/All-Of-Us-Mods/FusionCore/tree/0.045)
取得框架压缩包，安装 .NET 10 SDK 后运行：

```sh
python3 bazaarplusplus-android/build_probe.py \
  --framework-zip /path/to/FusionCore/fusionApp/src/main/assets/BepInEx-arm64.zip \
  --dotnet /path/to/dotnet
```

插件 DLL 生成在 `artifacts/probe/`；框架引用只供本机构建，不随插件复制。
使用 FusionCore 时，插件位置是
`/sdcard/FusionCore/<game-package>/BepInEx/plugins/`。此探针不包含自动部署步骤。

`runtime-probe/` 进一步注册一个 IL2CPP `MonoBehaviour`，在首帧记录回调，再等待
`Data.IsManagerCreated()` 后读取原生卡牌字典与一张模板。成功时写入
`bpp-android-runtime-probe.json`，记录帧、分辨率、卡牌数量和样本模板 ID。
读取失败最多尝试三次；不会创建 run、执行战斗或上传数据。

先使用加载器为对应手机版游戏生成 `BepInEx/interop/`，复制到本机，再向构建命令增加
`--interop /path/to/android-interop`，即可同时构建这个运行时探针。不要用桌面版 Managed
程序集代替。`probe/` 仍可在没有游戏程序集的情况下独立构建。

## 构建图鉴

在上面的构建命令同时提供 `--interop /path/to/android-interop --mod`。
图鉴 DLL 与包含框架、输入程序集、插件 SHA-256 的构建记录生成在 `artifacts/mod/`。
仅把 `BazaarPlusPlus.Android.dll` 放入加载器的 `BepInEx/plugins/`，不复制游戏代理或
框架 DLL。运行时探针会主动读取整个目录，日常使用图鉴时请把该探针移出 plugins；
图鉴本身在没有有效磁盘缓存时后台读取卡牌，再分帧创建托管快照；完整加载成功后写入本地缓存，
后续重启游戏优先读取缓存，卡面与详情模板按需读取。缓存校验游戏版本、静态数据及翻译清单的
SHA-256、当前语言和插件构建；变化或损坏时自动重建，缓存写入失败不影响浏览。
